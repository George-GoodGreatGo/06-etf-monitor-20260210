# 价值择时模块 Spec

## Why
目前“低波机会/红利择时”板块的核心利差口径基于股息收益率（分红贡献），但“自由现金流/红利质量/价值”这类指数更适合用估值（盈利收益率）来衡量相对债券的吸引力。新增“价值择时”模块并采用盈利收益率利差口径，有助于在同一套交互框架下提供更清晰的决策信号，并避免与红利口径混淆。

## What Changes
- 左侧导航新增一个模块入口：“价值择时”，交互与现有“低波机会/红利择时”保持一致（指数切换卡片、图表区、摘要区、错误/快照提示、展开/收起等）。
- 将以下 3 支指数从“低波机会/红利择时”模块迁移至“价值择时”模块：
  - 自由现金流（932365）
  - 中证红利质量（932315）
  - 国证价值100（980081）
- “价值择时”的核心利差改为：`盈利收益率(=1/PE) - 10年期国债收益率`，并同步调整利差分位计算基于该新口径。
- 页面文案明确说明：价值择时的“利差”采用盈利收益率口径，以区别红利择时的股息收益率口径。
- 价值择时使用独立的 Supabase 数据表与独立的 GitHub Actions 定时任务进行快照写入与更新（与低波机会快照任务分离）。

## Impact
- Affected specs: 左侧导航、市场页 Tab 体系、价值择时后端计算与快照、前端展示与交互。
- Affected code:
  - `src/components/SideNav.tsx`
  - `src/pages/Home.tsx`
  - `src/components/*`（新增价值择时面板与图表组件，复用现有样式与交互）
  - `server/routes/*`（新增价值择时路由）
  - `server/lib/*`（新增价值择时计算/数据读取模块；扩展 PE 数据源能力）
  - `server/lib/supabaseRest.ts`（新增表读写）
  - `server/scripts/*`、`.github/workflows/*`（新增 nightly 任务）

## ADDED Requirements
### Requirement: 左侧导航新增“价值择时”
系统 SHALL 在左侧导航中新增“价值择时”入口，作为 `/market?tab=value`（或等价路由参数）的导航项。

#### Scenario: 正常进入
- **WHEN** 用户点击左侧导航“价值择时”
- **THEN** 打开市场页并进入价值择时模块页面

### Requirement: 指数迁移
系统 SHALL 将 932365 / 932315 / 980081 从红利择时模块中移除，并在价值择时模块中提供同等入口与展示能力。

#### Scenario: 迁移后入口一致
- **WHEN** 用户进入红利择时模块
- **THEN** 不再看到上述 3 支指数卡片
- **WHEN** 用户进入价值择时模块
- **THEN** 可以看到上述 3 支指数卡片并可切换查看

### Requirement: 价值择时利差口径（盈利收益率）
系统 SHALL 使用 `盈利收益率 - 10Y` 作为价值择时的核心利差：
- `盈利收益率(%) = 100 / PE`（当 `PE <= 0` 或缺失时，该日盈利收益率为 null）
- `利差(%) = 盈利收益率(%) - 10年期国债收益率(%)`

#### Scenario: 利差计算与展示
- **WHEN** 某交易日同时具备 PE 与 10Y
- **THEN** 该日利差可计算并用于图表与分位

### Requirement: 利差分位计算同步变更
系统 SHALL 基于“价值择时利差(%)”计算滚动分位，并在 UI 中展示“利差分位(5年)”（窗口与最小样本数沿用红利择时的滚动口径策略）。

#### Scenario: 分位与利差一致
- **WHEN** 用户查看任意指数的价值择时图表
- **THEN** 利差曲线与利差分位均基于盈利收益率口径

### Requirement: 明确口径说明
系统 SHALL 在价值择时模块的说明文案中明确：
- “价值择时利差”使用盈利收益率（1/PE）口径
- 红利择时使用股息收益率口径

### Requirement: 980081 PE 数据源（推算口径）
由于国证指数（980081）缺乏可稳定获取的历史 PE 官方数据源，系统 SHALL 对 980081 使用“推算口径”的 PE：
- 使用跟踪该指数的场内 ETF（默认：159605）作为估值载体来源，并将其估值字段映射为指数 PE 序列用于计算
- 在 UI 上对 980081 明确标注“PE 为推算口径（基于跟踪ETF）”，避免与中证指数的官方估值口径混淆
- 在快照数据中记录来源信息（`source_type/source/notes`），以便排查与追溯

#### Scenario: 页面标注可见
- **WHEN** 用户在价值择时中查看 980081
- **THEN** 页面在 PE/盈利收益率相关位置展示“推算口径”提示（不影响其他指数展示）

#### Scenario: 历史区间不足
- **WHEN** 159605 的历史区间不足以覆盖 5 年窗口
- **THEN** 利差分位按“可用历史样本”计算或返回空值，并在 UI 中提示样本期不足（与推算口径提示合并展示）

### Requirement: 独立快照表与定时任务
系统 SHALL 使用独立 Supabase 表存储价值择时快照，并通过独立 GitHub Actions 定时任务写入更新；失败需可观测（日志可定位到指数与步骤），且不得静默吞错导致前端误认为数据可用。

## MODIFIED Requirements
### Requirement: 红利择时模块指数集合
红利择时模块的指数集合 SHALL 移除 932365 / 932315 / 980081，其余交互与展示保持不变。
