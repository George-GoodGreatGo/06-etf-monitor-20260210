# 首页轮播进度条稳定性修复 Spec

## Why
首页语录轮播的进度条偶发出现卡死、不滚动或不显示，导致用户误判轮播状态并影响交互信任。需要定位根因并修复，确保在自动播放、手动切换和暂停恢复下都稳定可见且连续更新。

## What Changes
- 梳理并修复轮播“当前索引、自动播放计时器、进度动画状态”之间的同步时序，避免状态竞争导致进度条停滞。
- 统一进度条的重置与启动机制，确保在“自动切换、手动上一条/下一条、hover/触摸暂停与恢复”后行为一致。
- 修复进度条首屏与切换瞬间的可见性问题，保证组件挂载后可稳定渲染。
- 增加降级与边界保护：在 `prefers-reduced-motion`、页面不可见、极短停留时间等场景下避免异常状态残留。
- 增加针对核心场景的回归验证，覆盖“连续自动轮播 + 高频手动切换 + 暂停恢复”组合路径。

## Impact
- Affected specs: 首页沉浸式语录轮播交互、进度指示可用性与一致性。
- Affected code: 首页轮播组件、进度条子组件（或相关 hooks）、首页交互事件处理与样式动画定义。

## ADDED Requirements
### Requirement: 进度条连续性与可见性
系统 SHALL 在首页语录轮播中稳定展示进度条，并在每个轮播周期内连续推进。

#### Scenario: 自动轮播时进度连续推进
- **WHEN** 用户停留在首页且轮播处于自动播放状态
- **THEN** 进度条从 0 到 100% 连续增长
- **AND** 到达周期终点后切换到下一条并重新从 0 开始

#### Scenario: 手动切换后进度正确重置
- **WHEN** 用户点击上一条或下一条
- **THEN** 当前语录立即切换
- **AND** 进度条立即重置并按新周期重新推进

#### Scenario: 暂停与恢复不丢状态
- **WHEN** 用户 hover 或触摸导致轮播暂停后恢复
- **THEN** 进度条不出现消失、卡死或跳回错误状态
- **AND** 恢复后可继续稳定推进并触发下一次自动切换

## MODIFIED Requirements
### Requirement: 轮播交互与节奏（首页语录）
系统 SHALL 保障轮播“自动播放、手动切换、交互暂停”与“进度指示”之间的时序一致性，任何交互路径下进度条都必须可见、可重置、可推进。

## REMOVED Requirements
无
